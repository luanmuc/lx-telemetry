# lx-telemetry 压力测试计划 v1.0 · 2026-11-20

> 对象：`luanmuc/lx-telemetry`（公开仓），`main`，基线 **`bc1901e`**（含 LT-01~LT-07 修复，用例已扩至 9 条）。
>
> **本文件是该仓第一份压测计划。** 它没有服务、没有并发 API，压测对象是**入库函数的边界韧性**与**证据的不可损坏性**：脏 body 能不能被挡住、48KB 上限是不是真的、去重会不会把真数据也去重掉、巨量投递会不会把仓库撑爆。

---

## 0. 目标与边界

**目标**：用纯 Node 用例证明 ingest 在以下条件下**不崩、不越界、不误收、不丢证据**：

1. body 体积：**48KB 边界 ±1B**、600KB、2048KB
2. 结构畸形：非 JSON、数组、JSONL 多行、深嵌套、超长数组、NUL/控制字符
3. 契约漂移：未知字段、错误 `schema` 版本、非法 `device.id`、`ok > total`
4. 去重语义：同键并发、跨日、跨设备
5. 数据量：单日 1,000 / 10,000 条的追加耗时与行完整性
6. 围栏提取：多围栏、非 json 围栏、嵌套 ``` 、围栏内带前后空行

**边界（blocked）**：

| 项 | 原因 |
|---|---|
| 真机 App 投递（每天 1 次 / inFlight 单飞） | 无设备 |
| GitHub Issue API 侧行为（body 65536 字符上限、评论回写） | 需 PAT + 真实 issue，本轮不取证 |
| workflow `concurrency` 抢占实测 | 需 Actions 运行环境 |
| 源仓每日拉取链路 | 跨仓，需网络与公开 raw 缓存 |

## 2. 执行顺序

```bash
# 现有基线（必须先绿）
node --test test/ingest.test.js           # 5/0

# 新增压测（建议落成 test/ingest-stress.test.js，用 node:test 原生 runner）
node --test test/ingest-stress.test.js    # T1~T4/T6，29 例

```

> 所有用例必须写入 `DIGEST_DIR` 的 `mkdtemp` 临时目录，**不得污染仓库 `digests/`**（现有 9 条用例已用此模式，照抄即可）。

## 3. 阈值与判据

| 指标 | 阈值 | 依据 |
|---|---|---|
| 48KB 上限 | `>48*1024` 字节 → `invalid` | README 硬规则；GitHub body 65536 字符上限留余量 |
| 单条校验耗时 | < 5ms（10⁵ 次累计 < 500ms） | 纯函数 + 正则量级 |
| 千行追加载入 | < 200ms | `appendFileSync` 逐行写，机械盘也能满足 |
| 深嵌套 | 100 层不得栈溢出 | JSON.parse 原生限制约 10⁴ 层，100 层是安全下界 |
| 坏行 | 0 | 一行坏 = 一条真机证据永久损坏 |

## 5. 失败处置

1. 任一用例非 0 记失败，不以「大部分通过」代替；退出码取 `node --test` 本身。
2. 体积类断言失败先确认是**字节数口径**（`Buffer.byteLength`）还是字符数口径——README 写的是 body 大小，GitHub 限制的是**字符**，两者对多字节内容不同，必须在实现里说清。
3. 去重类断言失败先看 `digests/` 是否被历史数据污染（用例必须用临时目录）。
4. 真机与 GitHub API 侧行为保持 `blocked`，不得用「本地 5/5 绿」推断线上链路可用。

## 6. 覆盖只增不减

后续每次改 schema 或 ingest：**只加用例不删用例**；已废弃用例标 `~~删除线~~` 并注明替代项，保留编号连续性。改 schema 时必须同步验证「旧格式是否仍可入库」（若刻意不兼容，需在本表新增一条明确拒绝用例，而不是静默消失）。
